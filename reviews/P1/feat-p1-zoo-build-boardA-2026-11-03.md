## Findings by severity

1. **High, blocking yes — Heretic kernel support differs.** `src/wsp/edits/kernels.py:23` applies `min_weight` to every layer outside the kernel radius. Installed Heretic `modifiers/abliteration.py:340` skips layers whose distance exceeds `min_weight_distance`. With a nonzero floor (normal for this config), this edits many extra layers and changes the scientific treatment. Match the finite support and add boundary/outside-radius parity tests. Interpolation itself matches the embedding-offset, normalized linear interpolation. Note also that Heretic defaults to FULL row normalization; this implementation is an unnormalized projection variant and must explicitly identify that variant rather than imply default Heretic parity.

2. **High, blocking yes — extraction prompt differs from Heretic.** `src/wsp/edits/refusal.py:64-72` supplies only a user message. Heretic `model.py:565-600` supplies system + user, defaults the system to “You are a helpful assistant.” (`config.py:563`), fixes template date, and appends the resolved response prefix before extracting residuals. This changes both tokens and extraction position, especially for thinking templates. Dataset names, source split/column, last-token residual selection, fp32 averaging, per-layer normalization and good-direction orthogonalization agree in form. However, this code samples 128 of 400 rather than using the default 400, and does not record prompt indices or resolved prefix/template. Implement the matching formatting or explicitly configure and record a scientifically distinct extraction method, with mocked extraction parity tests.

3. **High, blocking yes — dry-run contaminates the production manifest.** `src/wsp/zoo/build.py:475-482,507-517` loads and appends to the same manifest used for real artifacts, without a dry-run marker. Reruns also append duplicates. Running the required dry-run successfully added artifact-free rows to the worktree-local zoo; afterward there were 62 rows, 47 unique IDs, and 32 rows without edit.json. Such rows can be sampled as task-vector parents (`build.py:298-306`), causing missing-file errors; duplicates bias sampling. Separate planning output, validate actual artifact existence and make real entry registration idempotent. Existing history is also an input to task-vector sampling, so identical config/seed alone cannot reproduce its choices after a rerun.

4. **High, blocking yes — silent family fallback confounds H2.** `src/wsp/zoo/build.py:355-364,404-410` removes configured ARA/LoRA families based on local module availability without logging the requested/available/skipped families or reasons in edit.json or manifest. The effective chain distribution therefore changes by environment under the same config hash. Actual inner families are recorded, but that does not expose the selection policy. Fail explicitly or record the effective policy and exclusions in durable artifacts; test it. The default non-dry build also stops at unimplemented ARA/LoRA, so this is a partial P1 implementation, not the full roadmap zoo.

5. **Medium, blocking yes — refusal-cache identity is incomplete.** `src/wsp/edits/refusal.py:30-50` omits dtype from cache matching, accepts mutable model revision `main`, and uses a shared cache filename. Dataset revisions, resolved model commit, tokenizer/template and direction-file digest are not captured by entry provenance. `config_hash` is written only after lookup and not checked; it also hashes parsed JSON rather than the raw YAML hash used in the zoo manifest. Changing extraction dtype can silently reuse old directions, while rebuilding the same descriptor can change deltas after upstream revision drift. Pin revisions and fingerprint all extraction inputs; link the resulting fingerprint to entries and test cache invalidation.
