# H5 editor implementation

Branch: feat/h5-editor. Read repository policy, Board C design, research protocol,
hypotheses and D1 before implementation. Baseline: 403 CPU tests passed.

Implemented supervisor-owned versioned probes, sequence metering, detached allowlisted
weight copies, rationale/bounded delta capture, JSON-lines disposable workers with Linux
seccomp allowlist and resource limits, explicit scripted completion registry, private
append-only trajectories, D1 effective-delta zoo registration, builder replay and model
configuration templates. CPU integration uses an in-memory causal model and tmp_path.
No paid providers, network models, GPU jobs or research results were run.

Production is deliberately disabled: external provider adapters must be explicitly
registered and pinned by their deployment. Board A isolation/split review, resolved
checkpoint revision, actual development-pool version/item disjointness and production
pilot measurements remain required. Config revisions are templates, rejected by the
writer until resolved. The worker offers Python and JSON/list algebra rather than torch;
filesystem opens/imports after initialization are denied by the kernel. Host GPU probes
execute in the supervisor, not in a separately isolated model-worker process. Their own
wall timeout cannot preempt a hung model invocation; this needs a dedicated worker before
production. Hidden summaries currently expose last-position activations only. No claims
of production readiness or blog reproduction.

Tests cover metering at 10/25/50, launch failures, hidden states, validation, isolation,
partial IPC timeout, memory failure, private logs, replay identity, D1/eval equivalence,
manifest round-trip and builder dispatch. A whole-suite palette invariant required adding
llm_edit styling. Final test and lint counts are reported in the implementation handoff.
