## Notes

**Q1 (P2 procedure; the basis of N7). The bundle builder does not check cleanliness.**
- `wme_c1_ctl.py:92-108` (`cmd_bundle`) copies the **working tree's** `src/`, including untracked files and uncommitted edits, plus `BUNDLE_FILES`. It stamps `CODE_SHA` = HEAD without checking the tree.
- `up` checks only the tracked tree, and only at `up` time (`--untracked-files=no`, `:165`). `code_identity` does the same.
- So a bundle built while `src/` was dirty, followed by a reset, passes every check. So does a bundle that carries an untracked `src/**.py`. The bundle sha256 is recorded but cannot be recomputed from the commit, because a tar.gz carries mtimes.
- For Phase L, the operator builds the bundle from a fresh clean checkout, with `git status --porcelain` (including untracked) empty under `src/` and `BUNDLE_FILES`, and records that output in the run log. This is the P2 text as written, so no new gate is needed.
- **N7, before the first confirmatory unit:** `cmd_bundle` refuses unless `git status --porcelain -- src <BUNDLE_FILES>` is empty, untracked files included. Alternatively it builds from `git archive HEAD`. Add a CPU test that covers both a dirty file and an untracked file.

**O2 (observation, no condition). A mid-flight stall inside a reader unit.**
- A `ProgressClient` stall (`HealthIncident`, R7) can abort an LLM-reader unit after some controller-side reader responses have already been received. That makes it an uncounted abort with partial outputs seen.
- The trigger is time-based (a 15-minute registered limit) and identical across arms, and the abort is charged. So I see no outcome-selection channel.
- H-E2 should still report aborted attempts per arm alongside the counted failures.

**O3 (observation).** The drill has no post-completion-traceback scenario. N1 is covered by the CPU unit test with a reader-arm fixture (`test_wme_c1_v2o.py:80`), which is what N1 asked for.
