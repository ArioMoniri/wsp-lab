## P2: the two memos, exactly as proposed

Both memos live in `e2arms.run_planner`, one per arm-episode:
- **`memo_r_of`** is keyed by the primitive-id tuple. A first visit goes through `Env.r_of_pids` (the R-cache, its misses and its tick). A repeat returns a copy and still calls `tick("e2_r_of")`.
- **`memo_predict`** is keyed by the sha256 of each trajectory's exact bytes (shape, dtype, data; row order and batch size included). A repeat returns copies.

There is no row deduplication and no thread change.

**Tests** (`tests/test_wme_c1_v3a.py`) use the production planner and the real episode on a fixture environment, with the real `RCache`:
- for `wm_e`, `statnn` and `field_ranked`, the memo-on payload equals the memo-off payload once the timing fields are removed;
- R-cache misses and the tick sequence are equal;
- a hit returns a copy, for the R vector and for the prediction arrays;
- the batch key separates row order, batch size, −0.0 vs 0.0 and dtype.

**Whole-episode check.** `scripts/wme_c1_p2_episode_check.py` uses the real `fit.pkl`, `library.pt` and 9B role map with B = 48, on this host at 1 thread. The field and the dev world are stand-ins.

3. A mismatch, or a missing eligible payload, is an incident (`e2_speedup_mismatch` / `e2_speedup_unverifiable`) and halts the run.

## P4: cap rule (`ctl cap-raise`)

The cap-raise path is a chair cap generation with rule `"P4"`. `runguard.p4_cap` checks that the basis adds up and reproduces the cap.

**Projection** = charged + Σ max(0, re-priced price − measured) + instance overheads.

**Instance overheads,** from the study log only:
- One launch at the mean of the last three complete parity-plus-main launches (parity + main − unit time): 2.186, 2.188 and 2.491, mean **2.288** GPU-h-eq.
- 27 remaining canaries at the median canary of generation 1, 101.0 s, which is **0.758** GPU-h-eq. The 27 are ⌈262/16⌉ + ⌈24/16⌉ = 19 for E2 and S-BoN, plus 2 × 4 for the later stages.

If the projection exceeds 110, the cap = projection × 1.10, capped at the $1,000 ceiling (185.9 GPU-h-eq at $5.379 per GPU-h-eq). Only one P4 raise is allowed, and it is recorded before the units it funds.

**Computed now.** These come from the committed code run on a throwaway copy of the study log, F = 1.30, with nothing written to the real log:

| term | GPU-h-eq |
|---|---|
| charged | 25.389 |
| re-priced remainder | 84.138 = confirmatory 69.149 − 0.766 measured, S-BoN 13.911, S-TE 1.845, bank 0 (already above its price) |
| instance overheads | 3.046 |
| **projection** | **112.573** (about $605.5) |
| **cap = projection × 1.10** | **123.830** (about $666.1) |

At GO the projection is recomputed when `cap-raise` runs, after the parity, resume and verification charges. The numbers will therefore be slightly higher. `cap-raise` writes the basis into the cap record.
