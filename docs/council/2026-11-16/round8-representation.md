## Memory contract: feasible collection requires new plumbing

All following sizes are **calculations**, decimal GB, using rounded parameter counts, not measured peaks. 9B bf16 weights cost about 18 GB; bf16 parameter gradients add 18 GB, already exceeding 32 GB before activations. An fp32 gradient copy costs 36 GB, exceeding 30 GB host RAM alone. 4B's analogous sizes are 8, 8 and 16 GB. No optimizer or fp32 master-weight copy is required for feature extraction.

The existing [`response_field.py`](../../../src/wsp/features/response_field.py) does two forward/backward passes per microbatch/objective, retains fp32 gradients and all CPU A/G factors, accumulates objectives in one artifact, and reconstructs dense spectral factors. CPU offload alone is insufficient. Its ordinary-Linear hook contract excludes fused/recurrent operators; mark unsupported tensors explicitly rather than silently assigning q=0. K-FAC is a Fisher approximation, not a Hessian.

Proposed collector:

1. Load bf16 checkpoint shards directly to the GPU with bounded staging; avoid a second complete CPU state dict. Keep the base on disk, patch only changed tensors, and never retain complete base and edited GPU models together.
2. For each objective and small layer group, enable parameter gradients only there. Replay the same auxiliary microbatches through the model, with non-reentrant checkpointing, `use_cache=False`, batch one and initially 256 tokens. Later frozen layers must still propagate derivatives. Free graphs per microbatch; stream selected gradients to disk or contract with the frozen action dictionary immediately. Recompute for the next group. Validate equivalence on CPU toy models before this implementation touches a target.
3. Collect Fisher hooks only for that group's supported Linears; process A and G sequentially. A 4096→12288 MLP needs 4(4096²+12288²) bytes ≈0.671 GB of fp32 factors; fp64 spectral audits, copies and eigensolver workspace add substantially. Share identical input covariance only after proving identical masks/counts. Cap the spectral worker at 8 GB; split or stop if actual workspace exceeds it.
4. Never form a vocabulary-sized output covariance: 248320² fp32 entries cost approximately **247 GB**. Embedding/row edits need a separately declared diagonal/projected approximation or linear-only coverage, shared by every arm. Preserve the original exact-factor implementation for comparison on covered modules; new approximations need a new schema.
5. Persist one objective/group at a time, with shapes, coverage, dtype, sample counts and hashes; stream contractions when scoring candidates. Full fp32 gradient storage across five 9B objectives would approach 180 GB, so collect only declared editable tensors and cache scalar/sketched sufficient statistics. Reserve disk before buying a bank; store sparse/factored edits and recipes rather than whole checkpoints.

Proposed resource gates: ≤28 GB measured GPU allocation plus a recorded free-memory margin; ≤24 GB process-tree host RSS, no swap dependence; bounded staging/eigensolver peaks and measured wall time. Reserved allocator memory and non-framework GPU memory must also be checked. These are engineering limits, not fit claims. If 9B misses them after grouped collection, select 4B before the bank. Profile actual hybrid-kernel backward and checkpoint compatibility; neither card certifies this collector.

## State/action tokens and SAE value

Use [`response_chart.py`](../../../src/wsp/features/response_chart.py)'s oriented coordinates: E_t=W_t−W_0, realised D_t=fp32(bf16(W_t+δ_t))−fp32(W_t), and fixed projections of W_0, E_t and D_t. State tokens carry role, layer, shape, presence/coverage masks, cumulative displacement, spectra and fixed base activation summaries. Action tokens carry operation, ordered position, dose, target rows/layers, direction coordinates, realised/intended norm ratio and rounding loss. Include signed overlaps with previous edits and field cross terms; norms and spectra alone erase cancellations and order effects. Base a/q are action-conditioned contractions, not autonomous state variables.

Reuse [`pool.py`](../../../src/wsp/features/pool.py)'s hybrid role taxonomy and [`stats.py`](../../../src/wsp/features/stats.py)'s statistics, but label its stable rank as top-eight truncated. Existing SVD paths compute full decompositions before truncation: budget and replace with versioned sketches where necessary. [`msrm/features.py`](../../../src/wsp/msrm/features.py) hardcodes 24 layers/186 slots; derive a fresh 32-layer schema rather than copying those constants. Test LoRA gauge invariance away from repeated-singular-value ambiguity; use subspace/projector comparisons at degeneracy.

Initial z₀ may contain gradients and activations measured on a separate auxiliary panel at W₀. During a claimed forward-free rollout, predict z₁…z_H; do not extract activations, gradients or SAE features at W₁…W_H. Algebraically updating weights is allowed; executing those weights on inputs is running the edited model. Re-linearised field collection is an explicitly costed oracle comparator, never part of the open-loop claim. Actual intermediate measurements are allowed as training labels and subsequent verification, behind the exposure boundary.

The fetched [SAE card](https://huggingface.co/Qwen/SAE-Res-Qwen3.5-9B-Base-W64K-L0_50) describes residual-stream TopK SAEs trained on **9B-Base**, width 65536, K=50, for layers 0–31. It suggests post-training transfer can be reasonable; this is not validation for our checkpoint. From its encoder/decoder shapes, one layer has approximately 537 million matrix entries: 1.07 GB bf16 or 2.15 GB fp32, excluding temporary activations. Never load all layers alongside 9B. Optional: one fixed layer, token chunks, sparse activation moments and alignment of residual-writer edit directions to decoder features. Check reconstruction error, feature activity and held-out prediction gain against equal-width random projections/PCA. Reject SAE dependence if transfer is poor or no incremental gain appears. Feature names cannot substitute for behavioral labels; frozen SAE features do not themselves model dynamics.

## Information-matched WSR comparison (Q5)

The fetched [repository](https://github.com/suayptalha/wsr), [reader](https://raw.githubusercontent.com/suayptalha/wsr/main/wsr/read.py) and [labels](https://raw.githubusercontent.com/suayptalha/wsr/main/wsr/labels.py) support the following separation:

- **Replication track:** same pinned target, exact WSR edits/replacement tensors, suite, judges, decoding seeds and up/down/same labels. Include block/row scaling, direction removal, noise and no-op; use one common eligibility set. Preserve WSR's implemented normal-reference significance calculation and minimum-effect rule for comparability; report continuous deltas and a paired uncertainty analysis separately. “Same” is unresolved. Published numerical replication requires their exact bank; the README says paper results are absent, so do not promise it from generated lookalikes.
- **Matched-weights track:** descriptions, decoded token strings/IDs, config, architecture and edit arithmetic supplied identically to all arms; give the reader read-only weight tools, and scripted baselines identical weight access. Original WSR's weights-only and text-only prompts differ in descriptions as well as access. Keep these historical conditions separate from the matched experiment.
- **Auxiliary-information track:** give StatNN, static residual and LLM reader the same base-field/probe summaries as the world model. Compare reader without tool, reader with a frozen world-model tool, and world model alone. Also give a tool-free reader the identical prediction JSON to isolate tool orchestration. A learned tool embodies target-outcome training exposure: disclose it and equalise development labels across learned comparators. This track cannot claim original WSR's weights-only information regime.

Proposed cap: **16,000 cumulative input+output tokens per edit/session**, including repeated context, reasoning where metered and tool returns; 1,000 final-answer tokens, at most eight tool calls and 120 CPU-seconds. Two independently seeded sessions per reader arm, identical reader checkpoint/settings and cap; report truncations as failures. Pilot 20 edits across three main reader arms costs at most 1.92 million tokens (20×3×2×16000), a ceiling, not an estimate. Count tool training, auxiliary collection and inference separately. Local reader serving must be sequential with target evaluation on the single GPU.

## First build and decision gates

Propose a separate exploratory pilot: 12 independent direction/seed roots with three-step trajectories, no-op/rounding controls and order reversals.
