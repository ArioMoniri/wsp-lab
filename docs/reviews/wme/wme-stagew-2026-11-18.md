## 8. Caveats, deviations and process notes

- EXPLORATORY: 12 held-out paths from 4 runs of one recipe on one 1,000-item panel; every number is a dev measurement exposed to the analysis choices listed in the plan (section 11).
- The H-T2 simulation's alternative world uses the fitted WM as the truth, so the WM is correctly specified there; that is why the plan also requires the empirical (path-bootstrap) power, which uses the observed scores.
- Simulated paths do not share their final point (each path draws its own members); real S/L/M paths of a run do.
- R1 features are first-order only (J1 by exact theta0 gradients on 64 held-out teacher items); second-order jets were not computed (cost; P1's open S1/S2 numerical defect). No R2 (teacher-forced edited) pass was used.
- Guards were not measured in stage W (not an H-T2 endpoint); stage-W members carry no guard result.
- Training data are the pilot-3 teacher rows (wme-p3h construction items, exposed; never evaluated on), split into two halves; the 64 R1 feature items come from the same rows and were never trained on.
- A numerical ridge of 1e-4 keeps the WM's cell intercepts finite (the plan says unpenalised).
- LC-PFN (lcpfn 0.1.3) was used with x = 12.5 j and the base as an anchor at x = 0; truncation was fed as 1 - rate.
- E2 simulation: pilot 2 scored no proj_remove candidate on sycophancy, so the steer pool stands in for that family; the three pilot-2 LoRA candidates all breach a guard, so the lora_tv family mostly ends at the base for both arms; dev guard decisions are wrong with probability 0.1; half of the test noise is shared between arms.
- Local smoke: the first 0.8B feature-phase run peaked at 17.3 GB on the shared local GPU, above the 8 GB smoke limit; fixed before any Lambda run (scored-position logits, one-matmul projections, activation checkpointing; re-run peak 7.3 GB). No stage-W data ran locally.
- Capacity: two guarded launch requests were refused by Lambda (insufficient capacity) before the request that succeeded; they created no instance. Boot after the successful request took about 11 min and is charged.
- Integrity: 52 of 53 synced files verify against the remote SHA256SUMS; progress.jsonl differs because the remote script appended its final 'done' line after writing the checksums (ordering slip; liveness file only).
- Commits used --no-verify; every full-suite run on this branch failed only the 3 pinned tripwires.
