## Findings

1. **Blocking — stale entries enter scores** (`src/wsp/agents/score.py:74`, `src/wsp/agents/reader.py:581`). The scorer scans every parsed file in the output directory instead of the manifest's IDs. A run resumed with a subset of IDs retains old entry directories and scores their old predictions, even though the new manifest excludes them. This contaminates held-out comparisons and misreports sample counts. Restrict scoring to and validate against the run manifest, or reject changed ID sets.
2. **Blocking — resumed provenance can be false** (`src/wsp/agents/reader.py:570`, `:595`, `:658`). Resuming after a code change skips identical prompts but rewrites the manifest with the current SHA for predictions generated by earlier code. Configuration omits the endpoint, output-token limit and token field, so a changed provider configuration can also reuse old predictions under a misleading run record. Preserve per-call provenance or reject incompatible resumes, including code and generation settings.
3. **Blocking — unredacted secrets in error/repr** (`src/wsp/agents/reader.py:361`, `:364`). A base URL containing credentials or a secret query is printed in repr; error bodies containing a key or custom-header value shorter than six characters are not scrubbed. Such errors are persisted to parsed.json. Redact all credential values and URL credentials, including short values.
4. **Non-blocking — requested dry command fails** (`src/wsp/agents/reader.py:683`). Dry mode requires --model, although the requested invocation omits it; adding `--model dry` succeeds.
