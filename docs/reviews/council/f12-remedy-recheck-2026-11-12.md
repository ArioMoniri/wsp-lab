## Two remaining defects

**A10: the base loader does not enforce the required leaf boundary.** The new guard rejects lexical/resolved prohibited paths and authenticates the principal population, zoo and G2 inputs. However, tok 828–835 and add 555–563 resolve only the Hugging Face cache directory, append a directory-level unauthenticated note, then call `pf.load_base_state`. That helper (`scripts/a5_power_fields.py:430–443`) calls `from_pretrained` without a confined local snapshot or per-leaf boundary. The resulting state hash is checked after library reads. A static symlink inside the allowed cache can therefore lead a library configuration/checkpoint read outside the boundary without any race. The notes in P 6954–6957 acknowledge directory checking; that acknowledgement does not meet O 61's explicit resolved-leaf requirement. These library reads are also not recorded as exact input leaves.

I confirmed the wrapper gap using only a temporary synthetic cache: `cache/config.json` linked to a temporary prohibited directory containing `{}`. A substituted loader reading that path returned successfully through `tok.load_base`; direct `boundary.resolve` on that same leaf refused it. This is a wrapper-level negative check, not an actual Transformers exploit test, and involved no real model/cache or outcome file. The actual helper's unrestricted library call establishes why the gap matters. Fix by validating and recording all resolved model/config/shard leaves before loading a confined snapshot, or by a launcher that enforces the required read boundary for library opens. Add a negative test for a static cache-leaf symlink. Hash equality after loading cannot supply read prevention.

Population projection is also applied after parsing the authenticated full snapshot (pop 616), not a parser that skips nonallowlisted values. This is disclosed rather than called zero-access; the pinned source was already audited as metadata. The decisive remaining A10 defect is the unconfined base-loader path, not a claim that snapshot metadata are measured outcomes.

**A19: resume finiteness/schema validation is incomplete.** Binding, duplicate-free prefix IDs, prefix/line hashes, source checks, atomic checkpoint replacement and exact completion are substantial repairs (tok 698–826). But `_check_row` at 749–769 validates key sets and token vectors, not numeric types/finiteness for row a/q and nested diagnostic fields. `guard.strict_json_loads` at 271–272 rejects `NaN`/`Infinity` spellings through `parse_constant`; ordinary JSON `1e999` decodes to infinity without that callback.

A second temporary synthetic check created one row with all required keys, matching ID/increment/source and checkpoint hashes, finite 42-column token vectors, and `"a": 1e999`. The full `load_checkpoint` returned that row with `math.isinf(row['a']) == True`. No frozen output was touched. This does not allege that the authentic frozen run contains such a value: ordinary strict builder serialization would refuse it. It shows that the explicitly required resume schema/finite boundary is not implemented completely, even with self-consistent checkpoint hashes. Validate allowed numeric/null types and finiteness throughout rows/details (including overflow literals), plus the relevant token-slot schema, or disable governed resume as O 70 permits. The no-resume requalification remains valid evidence for the frozen outputs.
