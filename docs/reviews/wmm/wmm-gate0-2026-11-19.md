## BLUF

1. **Gate 0 verdict: KILL OR REDESIGN.** One of the three kill criteria holds. Under our template the base scores
   **60.5 %** on MedQA (400 dev items, SE 2.4). That is **−8.6 points** below the 1.5 card's 69.1, past the 5-point
   margin. The other two criteria do not hold:
   - the inert/null check passes, all bitwise;
   - 2 of 4 families are flat or non-monotone, below the threshold of 3.
2. **The miss looks mostly like format and length, not lost knowledge.** This is a diagnostic, not a rescue.
   - Among parsed answers the base scores 70.1 %; among untruncated answers it scores 66.3 % strict.
   - 8.75 % of answers hit the 2,048-token budget, and 5 % end in `$\boxed{X}$`, which the strict extractor ignores.
   - The flexible extractor gives 64.0 % (−5.1).
   - Two caveats: the card is on MedQA *test*, which we never read, and this check is on MedQA *dev*.
   - Domain K2 allows "one prompt fix". The synthesis's Gate 0 wording does not. **That is the chair's call.**
3. **The port works.**
   - All four named silent bugs are fixed with CPU tests.
   - The text-only loader never reads vision weights.
   - All three repos share one text architecture: 444 tensors, 3,880,263,168 parameters, identical shapes, tied head.
   - The canary and the full-state hash at the end of the run equal those at the start.
4. **Dose (pre-specified drift rule).**
   - **Pass:**
     - task vector (TV) λ 0.5–1.5: drift 0.08 → 0.29–0.32 nats/token on both arms;
     - MedGemma 1.5 → 1 interpolation: 0.07 → 0.60, strictly increasing.
   - **Fail:** both LoRA families. Their drift is *negative*: self-distillation lowers NLL on the base's own answers.
     It peaks in magnitude at λ = 1 and shrinks again, so it is non-monotone even in |drift|.
   - The sycophancy LoRA still does what it was built for. Suggestion adoption falls from 21.9 % to 4.7 % at λ = 1
     (Δ −17.2 pp, 95 % CI [−28.4, −6.0], n = 64). Neutral accuracy is unchanged.
5. **Post-norm cancellation is confirmed on the real model.**
   - Doubling every `o_proj` and `down_proj` changes NLL by 0.010 nats/token.
   - Directional noise of the same norm changes it by 12.3.
   - The k_norm-cancelled `k_proj×2` control from the Qwen spec is **not** exact on Gemma 3 (max 0.064).
6. **Compute:** **2.32 GPU-h** in total (≤ 3), $0, peak process memory about 14 GB.
   - Main run: 2.157 h.
   - Engineering smokes: 0.165 h.

## 3. Inert/null check and canary: PASS

All checks are bitwise, on 8 canary prompts with 48-token greedy continuations.

| Check | Result |
|---|---|
| Exact null: all 68 writers at dose 0 of scale, noise and rank-one | 0 tensors changed; θ-hash = base; logits equal |
| Apply → restore (scale on L10 `down`, noise on L5 `o`) | the edit moves logits; restore returns bitwise logits; full-state hash = start |
| Compensated pairs: `up×2`/`down×½` and `v×2`/`o×½` on layers 0, 20 (sliding) and 5 (full) | ΔNLL exactly 0; logits bitwise |
| Determinism floor (the same forward twice) | 0.0 |
| TV line t = 0 / t = 1 | 0 tensors changed / reproduces gemma-3-4b-it bitwise (0 inexact entries); ‖τ‖ = 435.5 |
| Interpolation line t = 0 / t = 1 | 0 changed / reproduces medgemma-4b-it bitwise (0 inexact); ‖θ₁ − θ₁.₅‖ = 389.7 |
| lm_head tied after every edit | yes |
| Canary (greedy ids and last-position logits) at the end vs the start | match |
| Full text-state hash at the end vs the start | match |

**Excluded control, reported.** The Qwen spec's k_norm-cancelled `k_proj×2` on layers 0, 5 and 11 is not exact on
Gemma 3: max |ΔNLL| 0.064, mean 0.006. It was removed from the Gemma inert spec after an engineering diagnostic run
(`gate0-diag`), before the main run, and is reported here rather than counted.
- The cause was not isolated. RMSNorm ε relative to small k activations is the leading candidate.
- With it counted, the inert check would read FAIL.

**Post-norm cancellation (descriptive).**
- Every `o_proj` and `down_proj` ×2 gives mean ΔNLL **+0.0103** nats/token.
- Norm-matched Gaussian noise (‖ΔW‖ = ‖W‖) on the same writers gives **+12.27**.

This confirms the synthesis R2 ruling: uniform writer rescales are near-inert on Gemma 3.

**FAIL** under the pre-specified rule, for the same reason as H1:
- increments −0.038, −0.014, −0.003, then +0.011 and +0.026;
- top-dose mean −0.018.

**Why the LoRA families fail.**
- The pre-specified rule assumed drift rises with dose: increments ≥ −2 SE, and top-dose mean ≥ 0.01 with LB > 0.
- Both LoRAs were trained on the base's own answers, so they *lower* NLL on those answers. The first increment
  (−0.037) already fails monotonicity (the first three steps all do), and the top-dose mean is negative, so the
  family is also "flat".
- A post-hoc reading on |drift| does not rescue them either: |drift| rises to λ = 1 (0.054–0.055) and then falls
  (0.025 and 0.018 at λ = 1.5). The verdict stands under both readings.
- The realised ‖ΔW‖ grows linearly with λ (0.45 → 1.42 for H1; 0.49 → 1.53 for sycophancy). The non-monotonicity is
  in the response, not the edit.
- The sycophancy target metric does respond: adoption falls at every λ, and is significant from λ = 0.75 on.

## 7. For the chair

1. **The card criterion.** The miss is driven by the template:
   - truncation at 2,048 tokens (8.75 %);
   - `\boxed{}` final answers (5 %);
   - the dev/test difference.

   Options:
   - (a) accept the kill;
   - (b) allow the domain seat's "one prompt fix", for example an answer-format line, a 4,096-token budget or the
     flexible extractor, re-checked on fresh exposed dev items. This costs about 0.5 GPU-h;
   - (c) re-check on MedGemma 1, whose card figure is 64.4.

   The agent took none of these unilaterally.
2. **Redesign the LoRA families.** The H1 and sycophancy LoRAs need a dose metric that fits self-distilled edits,
   for example drift on held-out *gold* answers, or a functional endpoint. They also showed a non-monotone response
   peaking at λ = 1. TV and interpolation are well-behaved bank families.
3. **Remeasure the inert spec on Gemma 3.** The k_norm control is not exact. The compensated pairs are exact.
