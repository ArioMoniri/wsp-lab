## 2. Structure and decisive measurement

**Primary — layer-set ΔW encoder, item-level output.** Represent each edited tensor as role/depth-tagged tokens containing its canonicalized ΔW block (including signed low-rank projections where available), actual predecessor-relative norm, and edit-family/program metadata. A permutation-equivariant set encoder aggregates within and across layers; predict the per-item change in normalized MMLU-Pro gold-letter log-prob, then aggregate exactly as TF-v1 does. Keeping itemwise outputs makes the failure mode visible: whether the model predicts which questions move, not merely family means or one scalar edit size. Train and score only with frozen, source-closed splits; make no claim that this is a causal decomposition. The measured target is the §1 TF-v1 quantity: for each of 1,000 disjoint items, log-softmax the frozen answer-letter scores, select gold, and average edited-minus-actual-predecessor values in nats (root edits use matched base) (`docs/PREREG_H1_TF.md` §§1–2).

**Alternatives.** (1) A base-frame signed-projection / low-rank direction model (`U16ᵀΔWV16`) with a regularized head can win by preserving direction and layer/role locality that pooled statistics discard; compare against both original StatNN and StatNN augmented with the same projections (`docs/PREREG_H1_TF.md` §7). (2) A predecessor-conditioned probe/JVP model can predict item-logit changes by combining ΔW with activations on a frozen, disjoint probe panel; it can win where the same parameter displacement acts differently in different predecessor states. Include activation-only and probe-plus-Δ variants so any gain is attributed correctly. The extra forward/probe cost must be charged; this is evaluation avoidance, not a zero-forward audit (`docs/council/2026-11-05/round2-metrology.md` §1.2).

**Protocol and decision.** Use D3 only for development, and reserve genuinely fresh, source-closed components for a later confirmatory comparison; D3 was already used for P4 and TF qualification. Freeze all features, model seeds, nuisance fits, item IDs and splits before sealed labels. Mandatory comparators are StatNN, descriptor-only and Δ-norm; add activation-only for the probe alternative. Report residual MAE reduction and paired component and joint component/item-block intervals, with the same item draw shared across edits and references. For a structure-superiority claim, require ≥5% residual-MAE improvement over both StatNN and descriptor-only, positive paired intervals, and MMLU ρ≥0.6 as the registered H1b screen; it remains descriptive until an untouched, multiplicity-protected, ≥80%-powered test (`docs/PREREG_H1_TF.md` §7). H1a’s θ≥.15 is a separate qualification target, not proof that the architecture beats StatNN (`docs/PREREG_H1_TF.md` §§1,4).

**Exact label and cost.** Keep the registered TF-v1 MMLU-Pro endpoint and 1,000 disjoint items; do not silently substitute option-text likelihood, accuracy or WikiText. However, the current MMLU qualification failure blocks confirmatory use. WikiText is a qualified fallback only for a separately named distribution-sensitivity question—not task readability—and its gate currently lacks power (`docs/PREREG_H1_TF.md` §§1–2; `docs/reviews/P5/tf-v1-requalification-2026-11-06.md`; `docs/reviews/P5/h1w-gate-2026-11-06.md`). Warm TF-v1 scoring is about 1.04 min/entry; 100 one-row fresh components therefore cost ≈1.7 GPU-h for labels, excluding closure ancestors, retries and references. Feature extraction is 54 s/entry and predictor runs are 1–10 min CPU; price closure separately after the manifest census (`docs/reviews/P5/d8-regeneration-2026-11-06.md` §§2,5; council brief). No fresh MMLU scoring is justified until a dated amendment resolves qualification and the registered conditional and joint power lower bounds both reach .80 (`docs/PREREG_H1_TF.md` §§5–6; `docs/reviews/P5/tf-v1-requalification-2026-11-06.md`).

## 3. H2 with regenerated chain deltas

The 358 missing deltas are all chain entries; they are not 358 independent examples. Regeneration restores weight inputs and feature extraction, but does not create item labels, ancestry closure, or independent roots. Before any training: reconcile each restored delta and alias to the manifest; resolve complete predecessor, source, optimizer/checkpoint provenance; deduplicate measured H1 states; then count eligible independent complete-run lineages and their ≥4-node rows. The recovered P4 suite itself lost 121 chain rows under the complete-ancestry feature rule and contained only 50 matched chain rows, illustrating why row count is not closure (`docs/reviews/P5/d8-regeneration-2026-11-06.md` §§1–2,6; `docs/reviews/P4/d3v2r-summary-2026-11-06.md`).

For the eventual test, freeze one M2 architecture and initialization/training budget. Compare true history against masked history, causal within-lineage shuffle, and lag/trend controls while holding the current cumulative state and incremental edit identical; hold out whole connected runs. Primary label is the same qualified 1,000-item TF-v1 MMLU gold-letter log-prob change. Require ≥15% residual-MAE improvement, a positive joint 95% bound, and a length-one placebo’s *entire* 95% CI inside [−.05,+.05]. Re-estimate variance and power on TF-v1 development losses; the old 162-lineage estimate uses a small accuracy-endpoint stand-in and is not TF power. If the restored census cannot supply enough independent closures, add new long lineages or leave H2 unresolved—do not count checkpoints as independent (`docs/PREREG_H1_TF.md` §7; `docs/council/2026-11-05/round2_metrology_output.txt`; `docs/council/2026-11-05/round2-metrology.md` §1.1).

An illustrative lower-bound price is 648 scored nodes for 162 four-node lineages × 1.04 min ≈11.2 GPU-h; longer closures and reference/retry overhead increase it. The earlier estimate was 7–14 GPU-h for 426 closure entries, based on the then-assumed 1–2 min TF-v1 rate (`docs/council/2026-11-05/round2-metrology.md` §1.1, §4.8; `docs/reviews/P5/d8-regeneration-2026-11-06.md` §5). H2 remains parked: first provide a cached closure/cost/power census; any scoring/training needs separate funding and amendment (`docs/PREREG_H1_TF.md` §7).

## 4. Editing models; table of tests

For `llm_edit`, score the validated effective delta from the pinned base, and retain every proposal—including failures and unselected proposals—in the episode record. Log rationale/transcript, but do not feed rationale to the primary predictor: it can leak the goal or encode editor selection rather than weight effect. A separately preregistered transcript-augmented arm may test utility; freeze transcript availability before the proposal and compare with delta-only. Match proposal-support/sparsity/norm controls and compare equal-budget best-of-N to best-of-N; otherwise archive selection creates the Meta^n order-statistic advantage (`docs/H5_DESIGN.md`; `docs/HYPOTHESIS.md` H5).
