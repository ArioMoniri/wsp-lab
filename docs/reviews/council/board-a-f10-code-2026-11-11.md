## Conditions required before code merge

1. **Implement the registered near-cut rank budget, not exact rank equality.** `src/wsp/features/rotation.py:290–297` requires `pre_rank_d == pre_rank_r`. It neither computes `N_near` nor logs the two cuts. F10a.1 requires strict own-leading-singular-value cuts and `abs(rank_R-rank_D) <= N_near`, with an inclusive near-cut window. Add the ranks, both cuts, window and budget to variant diagnostics and exported audit rows. In `tests/test_rotation.py`, add cases at the exact rank cut and both window endpoints, just outside each endpoint, both rank-change directions within budget, `N_near=0`, different leading singular values exposing an incorrect shared cut, and rank difference exceeding budget. Within-budget differences must pass this construction criterion; above-budget differences must produce `construction_failed`, while the other construction tests remain independent. Current rank-equality assertions exercise none of these allowances or boundaries.

2. **Use the fixed one-fp32-spacing bound and test its arithmetic boundaries.** `rotation.py:221` uses `2 * ulp_fp32(abs(W)+abs(R))`; F10.3(iv) fixes one `ulp_fp32(fl32(W+R))`. The implemented allowance is different, especially under cancellation. In-memory review confirmed the helper accepts an error above the registered one-spacing allowance when the `min` term is zero. Implement exactly the registered formula with the registered fp32 addition followed by bf16 rounding. In `tests/test_rotation.py`, extend `test_round_to_nearest_bound_uses_the_result_grid` with positive and negative signs, both directions across binade boundaries, midpoint ties on both sides, cancellation, signed zero, bf16/fp32 subnormals and zero floors, and overflow/nonfinite arithmetic. Include a genuine double-rounding case that fails without slack but passes with exactly the registered slack, and deliberate errors just beyond that bound which must fail. Current coverage checks one positive binade crossing and one large corrupt increment, not these boundaries.

3. **Apply the pooled half-norm guard to D, on both sides.** `rotation.py:233–237` and `response_intervention.py:313–320` instead require `sum ||R_eff||² >= 0.5 sum ||R||²`. Registration requires `abs(sqrt(sum ||R_eff||²)-sqrt(sum ||D||²))/sqrt(sum ||D||²) <= 0.5`. The current rule rejects some permissible losses and has no upper guard. In-memory checks confirmed both discrepancies. Fix the helper, caller, metadata, dry-run labels and misleading energy-guard wording. In `tests/test_rotation.py`, replace the present squared-energy boundary test with exact and just-outside lower and upper norm boundaries and an independent D reference. In `tests/test_response_intervention.py`, test pooled multi-tensor weighting, a small tensor rounding away while the pair passes, and pair exclusion with `sub_resolution` on either side. Assert no staged pair bytes/manifest eligibility on exclusion, with ladder eligibility retained. Current sparse-residue and large-companion tests are useful but do not establish the fixed boundary.

4. **Replay after writing and reloading, with bit-pattern equality and four recorded threads.** `f10_tensor_audit` performs an in-memory replay before `write()`; `response_intervention.py:496–529` writes increment/cumulative files without reloading them. Both replay and scorer-roundtrip comparisons use `torch.equal`, which is floating equality and does not distinguish signed-zero bit patterns. Root `delta.safetensors` and chain `increment.safetensors` must be reloaded and compared with freshly seeded replay bytes. Separately reload chain cumulative delta, reconstruct with the actual scorer base, and check the intended successor, including carried predecessor changes. Record/enforce the four-thread OMP/MKL/Torch settings and identify the numerical environment sufficiently for reproduction; current source provenance is not an environment pin, and the dry-run example sets OMP only.

   In `tests/test_response_intervention.py`, add post-save corruption and missing-file/key/shape/dtype cases for root delta, chain increment and chain cumulative delta, including signed-zero bit corruption; each must exclude the entire rotation pair with `replay_failed` and retain its ledger entry. Include a successful chain where the *same edited tensor* already differs between base and predecessor, plus unchanged predecessor tensors carried bitwise. The current positive chain fixture changes a different predecessor tensor; the negative roundtrip fixture supplies useful same-tensor cancellation coverage. In `tests/test_rotation.py`, retain the wrong-seed failure, explicitly prove the shared generator state is unchanged, and test interleaved unequal tensor shapes/reordering against fresh per-tensor seed reconstruction. Run committed replay tests with four threads despite the conftest cap. Existing equal-shape tests establish cloned-stream behavior but do not establish on-disk replay.

5. **Fail closed with recorded reasons on incomplete/nonfinite audits and check D support.** `rounding_bound` counts `err > bound` without a finite check: the in-memory NaN probe returned `passes=True` and a NaN diagnostic. Finite D is checked before construction, but finite W/R/R_eff, arithmetic and returned diagnostics need explicit validation. Missing audit coverage is not checked against the full edited-tensor set; `_f10_edit_audit({})` raises `ZeroDivisionError` instead of producing a recorded failed audit. Treat absent/invalid audit information as exclusion, without emitting a pass or a success manifest. Do not rely on an SVD exception or nonstandard JSON NaN to stand in for a reasoned audit.

   `rotation.py:303` checks R_raw/R_eff outside the supplied block but omits D. An in-memory check with nonzero D outside supplied rows/cols returned F10 `passes=True` and `support_identical=True`, while its realised S31 support diagnostic failed. Production `changed_block` normally prevents this input; the audit itself nevertheless does not implement the full support predicate.

   Add `tests/test_rotation.py` cases for NaN/Inf in every audited arithmetic input and nonfinite outputs, independently corrupt D/R_raw/R_eff outside the block, and force orthogonality, fp64 reconstruction, norm and spectrum failures independently. Expected results are failed checks with the specified reason, not accepted NaN, accidental masking by an earlier failure, or an unhandled exception. Add `tests/test_response_intervention.py` cases deleting one tensor audit, deleting a required metric, returning a nonfinite metric, and removing all audits from an otherwise eligible multi-tensor edit; require whole-pair exclusion and a retained reason/ledger. The current pre-audit NaN test only tests `exclusion_reason(D,...)`. The current F10 support corruption also fails construction first and never establishes the standalone `support_failed` reason.

6. **Preserve the complete original a533 verdict as a diagnostic.** F10 computes `rotation.audit` and logs `s31_passes`, and the pooled `realised_s31_passes` is its conjunction. That preserves realised norm/spectrum/rank/support tolerances. It does **not** preserve the complete original `a533` pass: `_rotation_diagnostics` also conjuncts its original fp32 reconstruction and orthogonality criteria. F10 replaces reconstruction with fp64 and never computes/logs that original full verdict. This matters specifically for the fp32 reconstruction failures in design §1.3. Compute the original audit alongside F10, distinguish S31-only and complete-a533 verdicts, and record tensor/pair diagnostics without using original failures as F10 exclusion reasons. In `tests/test_response_intervention.py`, compare these logged diagnostics with an explicit `audit_rule="a533"` run; include a deliberate original reconstruction-only failure with otherwise passing S31 and F10 arithmetic. Require original-a533 failure to remain visible while F10 eligibility remains governed solely by F10.

7. **Complete F10.4 diagnostics and test values, not just field presence.** Per-tensor κ, ε-hat, ε_R, root ε_D, τ, energy ratio and signed norm are substantially implemented. However `_f10_edit_audit` lacks pooled κ/ε-hat, root ε_D, explicit pooled energy ratio (only its logarithm), and pooled realised spectrum/rank/noise-rank reporting; maxima and `all(...)` verdicts are not those quantities. Implement the required pooled reports with explicit aggregation definitions, consistent with the design note's pooled rounding scale. Do not invent a single pooled matrix shape for τ: record the tensor noise scales and define any pooled rank/spectrum summaries transparently before re-stage. Carry unavailable raw-step ε_D as unavailable for non-root chains; do not imply the heuristic rounding floor bounds the missing raw update.

   In `tests/test_rotation.py`, add independently computed expected noise ranks at their strict cut, cases where each noise-calibrated diagnostic component deliberately fails, and prove those failures alone do not exclude an otherwise F10-valid tensor. In `tests/test_response_intervention.py`, add unequal-size/unequal-norm multi-tensor pooled-value checks, root versus non-root ε_D handling, complete audit-row/manifest exports, logged moments/nonzero masks and unrotated counts on exclusions. Current diagnostics tests check several real formulas, but noise ranks are only checked for presence and the noise verdict is recomputed from the implementation's own rank outputs; pooled scalar checking uses a single tensor.

8. **Provide an outcome-free re-stage route and its path-access test.** The dry-run script's call graph is CPU-only: `load_base_state` uses local cached weights and `device_map="cpu"`; `build_variants`, `manifest_for` and `audit_rows` do not read evaluation files or score. Keep the audit-only route separate or add an explicit outcome-free preparation mode. In `tests/test_response_intervention.py`, guard evaluation-file access and scorer invocation so an audit-only root/chain preparation succeeds without either; retain synthetic scoring-plan tests separately. Add a scratch-path/write audit for the dry-run entrypoint. Do not run ordinary real-data `prepare` under this review's no-evaluation-access restriction.
