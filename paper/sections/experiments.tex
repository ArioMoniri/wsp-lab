\section{Experiments}
The subject is Qwen3.5-0.8B with thinking enabled. Fixed subsets cover GSM8K, MATH-500, IFEval, MMLU-Pro and HellaSwag, with WikiText perplexity, harmful-prompt refusal, harmless-prompt over-refusal and KL to the base. Loop rate is the fraction of generated responses reaching the token limit. Refusal keyword matching is a surface measure and does not establish harmfulness.

The proposed fast screening tier uses 50 GSM8K, 25 MATH-500, 25 IFEval, 100 MMLU-Pro and 100 HellaSwag items, and 50 prompts each for refusal, over-refusal and KL, with a 1024-token generation limit. The cheap tier uses the larger fixed battery and a 4096-token limit. A faithful 32768-token tier is reserved for the base and selected entries. Fast scores are the proposed predictor targets; cheap scores will calibrate a subset. The planned evaluation order begins with a clean timing measurement and a stratified production subset, before extending coverage. Sampling settings and fixed item IDs are recorded in the evaluation configuration.

Table~\ref{tab:base-repro} gives the completed base run and the blog comparison recorded in \texttt{docs/RESULTS.md}. The budgets and loop denominators differ, so these are not matched estimates. The 32k rerun was interrupted by GPU memory exhaustion; IFEval differences also require checker reconciliation. Local work uses an RTX PRO 4500 with 32 GB; the ARA family is planned for Lambda GPU compute. The current decision specifies an H100, so an A100 run is not established by the recorded evidence.
