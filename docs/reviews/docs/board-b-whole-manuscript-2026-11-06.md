# Board B whole-manuscript review

**Verdict: MAJOR REVISION**

1. **[BLOCKING] Double-blind leak — `paper/main.tex:11`.** “`\author{Ario Moniri}`” is outside the `\ifarxivpreprint` switch. The TMLR PDF may render anonymously, but the source submitted for review contains the author identity. Move the author name inside the preprint branch and leave the review branch anonymous.

2. **[MAJOR] Recovered-set ordering claim is false — `paper/sections/experiments.tex:85`.** “The ordering of Table~\ref{tab:v2-suite} therefore holds on the recovered set: StatNN is at or above every neural predictor on both targets” is contradicted by the recovered family split. For example, StatNN is −0.18 on MMLU-Pro while M1-matched and M6 are 0.10 and 0.18; on HellaSwag, M1 is 0.16 versus StatNN at 0.06. The discussion itself reports neural rows exceeding StatNN on the family split. Restrict the ordering claim to the seed and trajectory splits, or describe the family-split exceptions explicitly.

3. **[MAJOR] Reproducibility access is incomplete — `paper/sections/appendix.tex:5,10`.** “The public Hugging Face dataset (`…handle withheld for review…`)” gives no anonymous access link, and the manuscript provides no anonymous code link. This matters because the primary protocol-v2 fold tables and run directories are lost and the 345-row results are explicitly retained-log reports; readers cannot retrieve the surviving artifacts or independently reproduce the recovered rerun from the cited internal document paths. Supply anonymized links to the dataset and code, with the exact code revision/configuration for the recovered rerun. If that cannot be provided, state the access limitation and narrow the reproducibility claim accordingly.

4. **[MINOR] Feature-recovery status contradicts itself — `paper/sections/method.tex:4`; `paper/sections/zoo.tex:29`; `paper/sections/appendix.tex:8`.** The main text says “the feature files were lost … and are being re-extracted” and “No feature count or failure count is reported until re-extraction finishes”; the appendix says “Feature re-extraction covered 901 entries with no failure.” The first two statements are stale and make the recovery status unclear. Update them to report the completed 901-entry extraction and distinguish it from the unrecoverable pre-incident feature files.

5. **[MINOR] Broader-impact note is missing — `paper/sections/abstract.tex:4`.** “The paper concerns prediction and auditing, not gradient-free optimization or a new safety-editing method” defines scope but does not assess broader impact. Given the stated use of predictions to prioritize edits and flag capability costs, discuss the risk that inaccurate rankings or overreliance could defer necessary evaluations, and clarify that no safety benefit is established.

6. **[MINOR] Compute statement is not complete — `paper/sections/experiments.tex:33`.** “Measured runs used four hosts” and the hardware/hourly price identify machines but not total compute. Report GPU-hours by host and the predictor-training/evaluation budget, or explicitly state which totals cannot be recovered.

7. **[MINOR] Contribution framing is buried and duplicated — `paper/sections/discussion.tex:41`.** “If no gate passes, the contribution is a measurement and benchmark report with its negative results. It is a measurement and benchmark contribution with a scoped, underpowered negative on confirmatory readability.” The second sentence repeats the first, while the conditional weakens the paper's actual reframing. State the measurement/benchmark contribution once in the abstract or introduction and remove the duplicate.

8. **[NIT] `StatNN` is undefined and misleading — `paper/sections/abstract.tex:1`; `paper/sections/method.tex:6`.** The abstract uses “StatNN” before definition; the method identifies it as LightGBM, not a neural network. Define it on first use and explain that `StatNN` is a retained baseline label, or use an unambiguous name such as “statistics-only LightGBM.”
