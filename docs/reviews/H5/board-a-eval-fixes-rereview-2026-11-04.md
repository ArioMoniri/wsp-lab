# Board A: eval fixes re-review

Date: 2026-11-04. Reviewed commit 58f7ee6. Verdict: **REVISE**. This does not qualify the measurement panels.

## Blocking findings

1. **Runtime provenance is misstated for local backfills.** `backfill_eval_metadata.py` fills missing local runtime fields from the current machine and marks them `transcribed` by default. D2 explicitly admits these are not contemporaneous measurements. Consequently `full`, the matched counts, and `targets_with_inferred_runtime` understate uncertainty. Mark these fields inferred (or unknown), propagate the revised status and counts, and disclose the source and limitations. H1's config also calls transformers transcribed whereas the supplied implementer report says both Lambda versions were inferred: reconcile against contemporaneous evidence rather than relabel by assumption.
2. **Reliability pairs are not fully validated.** `compare_pairs` checks edit and item hashes but does not enforce runtime/config/seed compatibility or reject changed actual batch; it merely reports `batch_size_mismatch`. Its item bootstrap pools observations across edits as independent items, and the claimed WikiText window-block bootstrap samples individual windows. Matched-reference delta item uncertainty, paired reference covariance, exponentiated WikiText intervals and the registered host-by-edit analysis are not implemented. Do not call the preregistered reliability calculation complete; implement and test these or explicitly leave the qualification analysis blocked.
3. **19 local matches remain unresolved.** All 19 match a local reference on device, both item hashes and batch, but differ in `source_hash` (18 random_dir, one abliteration). `source_hash` covers all Python under `src/wsp`, so it may reflect unrelated code; equality of the other fields does not prove the difference cosmetic. Identify both historical source trees and audit the evaluator, parser, generation and benchmark paths. If demonstrably score-neutral, preserve original hashes and add an explicitly documented, evidence-backed evaluator-equivalence mapping, with tests; otherwise retain missing and rerun matched bases. Do not silently overwrite hashes or relax matching globally.

## Previous findings and evidence

Matched references are now used in delta target construction, with missing counts and inferred counts; unknown values are rejected. Reference selection and base resume logic are substantially improved, and `--no-base` reports missing references. The wording in research notes has been corrected. These changes address the earlier findings in part, but the provenance and reliability defects above prevent closure. Summary statistics now include RMSE, absolute median/max, SD, Bland–Altman limits, rank/ICC bootstrap intervals and boundary Wilson-based uncertainty; their existence does not establish the full preregistered analysis.

The data report ran and returned 221 matched, 58 missing and 167 inferred: 37 unevaluated chain predecessors, 19 local source-hash mismatches, and two H2 batch mismatches. A dry run of the backfill with the supplied runtime file returned 310 files and zero changed, evidence of idempotence for this snapshot. Inspection shows the backfill copies payloads and adds/removes metadata rather than rewriting score keys, but no independent before/after score diff was established; require an archived-original comparison or independent re-derivation before asserting score preservation. Resume-key preservation was not independently verified across historical records.

Inference from an identical same-day bootstrap is plausible for exploratory matching, conditional on evidence that both jobs actually used that bootstrap and settings; it is not measured equivalence. The paper must report the inference, fields and counts, local current-environment assumption, missingness, possible misclassification, and a sensitivity analysis excluding inferred pairs. It must not claim independently verified runtime equivalence or panel qualification.

The M1 compatibility run was launched with real data, one epoch and ten bootstrap samples in `boardA-eval-rereview3`; it completed five folds successfully. The captured output did not demonstrate an empty-fold warning. Code in `FeatureDataset.folds` records `skipped_reason` and emits a warning for empty ancestry-purged training folds, but the warning was not observed in this run. No GPU evaluation was run. These verification gaps remain open.
